# The capability register of the interface.
#
# One record per capability of the interface: the capabilities of AfterNight 1.1, then the ones the new interface
# adds. A record names the cases that prove the capability:
#
#   shared       cases of code every shell uses - a dialog, a control, a model
#   classic      cases that drive the classic shell's own window
#   observatory  cases that drive the Observatory shell's own window; `pending` until they are written
#
# A case is named as Google Test names it: `Suite.Case`, and a parity scenario run for one shell
# `ShellScenario.Case/<shell>`. An empty `classic` line is a capability 1.1 has no case of that kind for. The cases
# named are the ones that most directly prove the capability, three of a kind at most: the register says where a
# capability is proved, not everything that touches it.
#
# build/scripts/tools/check_shell_capabilities.py holds the register to the suites: every case it names exists, no
# capability is listed twice, and every capability has an `observatory` line. A capability the interface gains is added
# here in the change that adds it; one it loses goes with it.

# ---- Covered less than their lines suggest
#
# Read before a capability's cases are written.
#
# dock.all-floating: no case of either kind; nothing floats every image. dock.lock: nothing reads the default in
#   Settings.
# dock.tabs, dock.float, dock.tab-buttons, dock.no-image: only flags and decision helpers are tested; no case drives
#   a dock.
# window.main-toolbar, window.dock-toolbar, dock.group-split-fit: the classic cases trigger the actions the toolbars
#   hold, not the toolbar buttons.
# home.recent-menu: the case pins through the model; nothing opens the thumbnail's menu.
# view.display-mode, view.overlays: proved through the static preview, which shares the view's toolbar.
# The window-geometry cases named under `classic` do not build the main window; they test its size rules.
