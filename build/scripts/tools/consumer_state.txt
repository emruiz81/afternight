# The consumer process-state register: every object with process lifetime that the product's own
# libraries and executables declare, who owns it, how long it lives, how access to it is ordered, and
# why it exists at all.
#
# `build/scripts/tools/check_consumer_state.py` reads this file and holds the tree to it in both
# directions: an object the product declares with no entry here fails, and an entry naming an object
# that is gone fails. It is the product's counterpart of the engine's process-state table, kept
# separate so that neither set of rules bends the other. The categories and where each may live are
# stated in that script.
#
# A value declared `const` at the head of its declaration is exempt and is not listed. A class's static
# data member appears twice, once where the class declares it and once where its storage is defined,
# because the reader sees both and a reviewer should too.
#
# Record format - one per object, fields indented four spaces, a field continuing onto any line indented
# further:
#
#   state <path> <symbol>
#       scope            <the function or class the declaration sits in, or ->
#       category         platform-service | module-seat | application-seat | theme-service |
#                        ui-registration | ui-state | identity | constant | pending-rehome
#       owner            <what creates it and what ends it>
#       lifetime         <from when to when it exists>
#       synchronization  <how concurrent access is ordered; ui-state names the GUI thread or its lock>
#       reason           <why the process needs it; for pending-rehome, what replaces or re-homes it>
#
# Lines starting with '#' and blank lines are ignored.
