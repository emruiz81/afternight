# The safety register: what was read about the advisories of every library the engine loads, and each finding
# about the engine's safety, with a severity and what became of it.
#
# `build/scripts/tools/check_safety_register.py` reads this file and holds it to the tree. A critical or high
# finding is resolved only by a repair that names the test or the release that carries it, or by showing it
# cannot happen in this engine - never by being accepted - and every advisory a review lists is answered by
# exactly one finding filed against that library. Every library `dependencies.txt` registers is reviewed at
# the version that register pins, and with `--binaries` every module the shipped engine binaries load from a
# Release deployment is reviewed too, because the loader brings in more than a build links and a hostile file
# reaches all of it.
#
# Record types, one per line, fields indented under their record. Lines starting with '#' and blank lines
# are ignored. A field continues onto any following indented line that does not begin a field.
#
#   review <library>
#       version     <the version the advisories were read against; for a library dependencies.txt
#                    registers, a token of the version it pins>
#       binaries    <the deployed files this library is loaded as, comma-separated, or none>
#       reviewed    <YYYY-MM-DD>
#       source      <where the advisories were read>
#       advisories  <every advisory that names this library and whose stated range includes this version,
#                    or that states no range yet, comma-separated, or none>
#       outcome     <what the reading found>
#
#   finding <id>
#       title       <one line>
#       severity    critical | high | medium | low - what it can do in this engine, not a published score
#       component   engine | python-adapter | gmic-adapter | opencl-backend | tests | tooling |
#                   dependency <library>
#       found       <what found it, and when>
#       status      open | repaired | not-applicable | accepted
#       advisories  <the advisories this finding answers, comma-separated, or none>
#       evidence    <repaired: `test <Suite.Case>`, `test <file.py>::<name>` or `release <library> <version>`;
#                    not-applicable: why it cannot happen here; open or accepted: who owns it and why>
#       record      <the file of this tree that carries the guard or explains the finding: the module, the
#                    overlay port's README or the guide>
#
# Severity is the effect in this engine:
#
#   critical    memory corruption or code execution reachable from a file, stream or buffer the engine is
#               asked to read, with no mistake by the caller;
#   high        memory corruption reachable through an argument a caller passes in ordinary use; a read
#               outside a buffer, or disclosure of uninitialised memory, reachable from a file; a crash, a
#               hang or unbounded resource use reachable from a file; a data race on a path an ordinary
#               caller takes;
#   medium      resource use a stated limit bounds and the engine's budget does not count; wrong output
#               without memory unsafety; a failure only a caller breaking a documented rule can provoke; a
#               deployment or tooling defect that can silently remove a protection;
#   low         a gap in evidence, tooling or documentation with no effect on a running engine.
#
# An advisory that does not apply is rated by what it would do here if it did.
