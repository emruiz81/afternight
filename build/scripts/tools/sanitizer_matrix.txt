# The sanitizer campaign's matrix: which instrumented configuration runs which tests, under which
# options, and what is deliberately not run and why.
#
# It is a file rather than a paragraph because a sanitizer run is worthless unless three things are
# known about it together: that the binary was instrumented, that the tests it ran were the ones the
# campaign claims, and that no option quietly turned a check off. A recipe typed into a shell
# establishes none of the three, and a clean run over an uninstrumented binary looks exactly like a
# clean run over an instrumented one.
#
# build/scripts/tools/run_sanitizer_campaign.py reads this file; nothing else does. The fuzz targets
# are not here: they carry their own instrumented build and their own budget in fuzz_targets.txt.
#
# Record types, one per line. Lines starting with '#' and blank lines are ignored.
#
#   configuration <name> build=<address|thread> hosts=<windows,linux> timeout=<seconds>
#
#       Declares a configuration. `build` is the value AFTERNIGHT_SANITIZE was generated with, and
#       the runner refuses a binary that does not carry that instrumentation. `hosts` is where the
#       configuration can be run at all - Microsoft's compiler has no UndefinedBehaviorSanitizer and
#       no ThreadSanitizer, so those are Linux rows and saying so here is what keeps a Windows run
#       from reporting a coverage it never had. `timeout` is the per-row wall-clock bound; a row that
#       exceeds it is a finding, because a deadlock is what half of this campaign is looking for.
#
#   option <configuration> <VARIABLE>=<value>
#
#       An environment variable every row of that configuration is run with.
#
#   weakened <configuration> <token> <reason...>
#
#       States why an option that turns a check off or lets a refusal through is set. Every such
#       token in the options above must have one of these, and a token that is no longer in the
#       options must not - so the reasons cannot drift away from the configuration they explain.
#
#   run <configuration> <label> <target> <selection> [repeat=<n>] [shuffle]
#
#       One row. `label` is `suite.<name>` for a direct suite or `pipeline.<name>` for a focused
#       pipeline, and is unique within its configuration. `selection` is `whole`, `filter=<gtest
#       filter>`, or `skip=<reason...>`, and a row that runs no test at all is a failure rather than
#       a pass.
#
# Every direct engine suite the generated tree defines must appear exactly once as a `suite.` row in
# every configuration, run or skipped with a reason, and every configuration must have at least one
# pipeline row. Both are checked, because a suite that quietly leaves the matrix is the way a
# campaign stops covering something without anybody deciding to stop covering it.

# ---------------------------------------------------------------------------------------------
# address - the address sanitizer, and on Clang the undefined-behaviour sanitizer with it.
#
# This is the configuration Windows and Linux both run. It owns ownership, bounds and lifetime
# everywhere, and on Linux it additionally owns conversion, overflow, shift, alignment and invalid
# value. Windows contributes the address half only: Microsoft's compiler has no UBSan.
# ---------------------------------------------------------------------------------------------

configuration address build=address hosts=windows,linux timeout=5400

option address ASAN_OPTIONS=halt_on_error=1:print_stacktrace=1:detect_leaks=0:allocator_may_return_null=1
option address UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1

weakened address detect_leaks=0 Leak detection is the `leak` configuration below, which is the same build run again with it on. Keeping it off here is not what makes leaks unreported; running this configuration alone would be.
weakened address allocator_may_return_null=1 Test_EngineRuntime deliberately asks the platform allocator for an impossible size and requires the engine to return an allocation-free failure. Without this the sanitizer runtime aborts that `nothrow` request instead of returning null, and the case never reaches the behaviour it tests.

# ---------------------------------------------------------------------------------------------
# thread - ThreadSanitizer.
#
# Linux only. It needs the separately instrumented oneTBB that build/scripts/linux/build_tsan_onetbb.sh
# builds, first in LD_LIBRARY_PATH, because a sanitizer proves a happens-before edge by watching the
# code that establishes it and this engine's edges are established inside that library. The runner
# refuses to start a thread row without it, rather than producing races that are an uninstrumented
# library's synchronisation being invisible.
#
# That same rule is why three suites are skipped here: their concurrency crosses into a library
# nobody has built an instrumented copy of, so what the run would report is the library's edges being
# unreadable rather than this engine's being absent.
# ---------------------------------------------------------------------------------------------
