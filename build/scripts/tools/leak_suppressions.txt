# LeakSanitizer suppressions of the `leak` configuration, read by run_sanitizer_campaign.py, which refuses an entry
# without a reason above it or one naming this engine. Each names a library AfterNight did not write and what the
# library keeps for itself. The full host and the runtime backend's suite finalize the interpreter they started;
# CPython does not give back everything an interpreter allocated when it is finalized - its static types, interned
# strings, and the state of the extension modules it cannot unload - nor do NumPy, pybind11 and PySide6 give back
# theirs. The entries name CPython's allocator rather than the interpreter's library, so an object of AfterNight's
# allocated while Python is on the stack is still reported; a Python object that AfterNight leaked a reference to
# is not, which a finalized interpreter would hide anyway.

# reason: pybind11 keeps one pointer to each module's local internals for the life of the process and never frees it; the host unloads the runtime backend before the sanitizer reads the stack, so its frames carry no name but the interpreter executing the built-in module that registered it.
