# The provenance register: every third-party library and every ported subsystem the engine retains,
# with the eight things somebody has to be able to look up about each of them.
#
# The scope is the engine and nothing else: `AfterNightEngine`, its two optional adapters, the
# opt-in GPU backend, the suites that link them and the benchmark layer that measures them. A library
# only the product links is outside it.
#
# It is a file rather than a page of prose because a provenance record written once describes the
# tree it was written against. Three things drift, and each of them drifts silently:
#
#   - a library arrives. A link line gains an entry, a codec gains an include, and nobody decides
#     that this engine now depends on something;
#   - a library leaves, and its record stays - so the register claims a dependency that is not
#     there, which is worse than no register at all because it reads like coverage; and
#   - a version moves. The number recorded here and the number inside the binary stop agreeing, and
#     the difference is invisible until somebody has to answer whether an advisory applies.
#
# `build/scripts/tools/check_dependency_provenance.py` reads this file; nothing else does. It reads
# the generated projects, the install and deploy scripts, the include lines of every engine source,
# the engine's own dependency report and the suite that pins it, and fails when any of them names
# something this file does not - or when this file names something they do not. `--installed`
# additionally compares every packaged version below against the package database of the host it is
# run on, which is the one check that needs a provisioned machine and is recorded per host.
#
# The engine reports the second half of this for itself. `Core/DependencyReport.h` answers, for the
# binary that is actually loaded, which libraries are inside it and at which versions - the version
# its headers declared and the version the loaded copy reports about itself. The `reported` field
# below is that report's shape, and the check holds it against both the engine and its suite.
#
# Record types, one per line, fields indented under their record. Lines starting with '#' and blank
# lines are ignored.
#
#   library <name>
#       role        <one sentence: what this engine uses it for>
#       kind        packaged | fetched | vendored | distribution | embedded | transitive
#       linkage     shared | static | header-only | mixed
#       version     <what is pinned, per platform where the two differ>
#       source      <where the artifact comes from: a package port, a vendored path, a download>
#       upstream    <the project's own home>
#       license     <the licence as shipped, and whose copyright where that matters>
#       security    <where an advisory about this library is read, and what this build pins>
#       build       <the script that installs or builds it>
#       deploy      <the script that puts its runtime beside the binaries, or why nothing does>
#       artifacts   <the tokens that script names, comma-separated, or `none` when nothing is
#                    deployed; they are checked against the script's own text, so a glob or a
#                    formatted name is written the way the script writes it>
#       boundary    <the only place in this tree that may reach it>
#       targets     <the engine-side targets that acquire it>
#       links       <the link tokens that name it, comma-separated, or none; a token followed by
#                    `(SWITCH)` is one only a tree generated with that switch carries>
#       reported    compiled=<yes|no> loaded=<yes|no>   (only for a library the engine reports)
#
#   ported <name>
#       role        <one sentence: what it does here>
#       files       <the repository paths that carry it, comma-separated>
#       marker      <a phrase every one of those files contains, so the attribution cannot be lost;
#                    `none` on a not-carried record, which has no attribution to keep>
#       upstream    <the project and work it came from>
#       author      <who holds the copyright upstream>
#       license     <the licence the upstream work carries>
#       relation    adapted | re-derived | replaced | not-carried
#       divergence  <who owns the difference between this and upstream, and what it is>
#       record      <where the audit's conclusions are written: a guide or a provenance note, beside
#                    the module comment of every file the record names>
#
# `kind` says where the artifact comes from and is what decides how a version is pinned. `packaged`
# is a vcpkg port at a version this repository's vcpkg checkout fixes; `fetched` is an upstream's
# published release, named as `owner/repository@tag` with the commit that tag resolves to, which build
# scripts of this repository fetch, verify and build, each naming that repository, tag and commit;
# `distribution` is a package
# the nominated Linux host installs, whose version moves with that host and is checked on that host
# rather than pinned here; `vendored` is a copy of somebody else's sources inside this repository;
# `embedded` is a runtime this repository downloads and ships beside itself; `transitive` is a library
# no source of this engine includes and a build of it links anyway, behind one that does.
#
# `relation` on a ported record says what was actually carried. `adapted` means upstream code is here
# and changed; `re-derived` means the method is here and none of the code is, written from a
# publication or a specification; `replaced` means the same, and specifically that upstream code was
# looked at and rejected for a stated reason; `not-carried` means an audit happened and nothing came
# across at all, which is worth a record because the alternative is a reader assuming it did.
